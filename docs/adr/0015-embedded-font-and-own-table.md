# 0015. Шрифт вшит в сервис, таблица рисуется вручную

- Статус: принято
- Дата: 2026-09-13

## Контекст

Задание требует текстовый PDF (не картинку) со свободным кириллическим шрифтом — PT Sans или Roboto с Google Fonts — и запуск одной командой, без внешних зависимостей во время работы.

## Варианты

**Шрифт:**
- **Тянуть с `fonts.googleapis.com` при каждой печати.** Добавляет сети ещё одну точку отказа поверх и так ненадёжной 1С; сервис перестаёт запускаться офлайн.
- **Вшить TTF в бинарник через `go:embed`.** Один файл шрифта, никакой сети при рендере.

**Таблица строк:**
- **Готовый табличный слой.** В `signintech/gopdf` (активно поддерживаемая, по [обзору gpdf.dev, 2026](https://gpdf.dev/blog/go-pdf-library-showdown-2026/)) специализированного табличного компонента нет; в `maroto/v2` есть, но это лишняя зависимость и абстракция ради восьми колонок.
- **Ручная сетка на `CellWithOption` с рамками.** Прямой код, весь макет виден в одном файле.

## Решение

- Шрифт **PT Sans** (Regular и Bold) взят из `google/fonts` (то же, что раздаёт `fonts.googleapis.com`, лицензия OFL) и вшит в `internal/infrastructure/pdf` через `go:embed`.
- Таблица строк собрана вручную поверх `signintech/gopdf`: фиксированные ширины 8 колонок на A4 (18+46+15+19+15+19+19+23 = 174 мм при полях 18 мм), перенос на вторую страницу при переполнении.
- Шапка таблицы — шрифтом meньшего размера (8pt против 10pt в теле): при равном размере с телом «Сумма с НДС» не помещалась в свою колонку и наезжала на соседнюю. Найдено визуальной проверкой готового файла, не только тестами на наличие текста.

## Последствия

- Печать работает без интернета и не зависит от доступности CDN.
- Извлечение текста (`ledongthuc/pdf` в тестах) подтверждает, что документ текстовый: родительный падеж ФИО, телефон, артикулы и итоги видны как текст, включая эталонные суммы задания (21181.00 / 3210.82 / 24391.82).
- Макет — обычный код в `render.go`, читается построчно, без DSL стороннего пакета.
- Ручная раскладка не умеет перенос строк внутри ячейки: очень длинное наименование товара выйдет за границу колонки, а не перенесётся. Пока в демо-данных такого нет; тест `TestRender_LongProductName_DoesNotBreakLayout` проверяет, что документ хотя бы не ломается.
